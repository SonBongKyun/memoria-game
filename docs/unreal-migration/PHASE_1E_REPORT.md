## Presentation replacement and input

`FMemoriaNarrativeView` contains only header, speaker, narration/body, ordered
choice text with original IDs, and temporary pause/status presentation state.
The widget displays values, keeps a visual selection, and emits
`FMemoriaPresentationConfirm(original_index)`. It contains no gates, rewards,
costs, jumps, run mutations, content loading or continuation interpretation.
The controller forwards that intent to the host, which calls the existing
dialect interpreter. Field's original-to-visible conversion is confined to its
host boundary. Replacing UMG/layout/typewriter/art therefore does not require
rewriting interpretation, run state, choice semantics or saves.

Accepted Enhanced Input assets/actions are reused. The base controller exposes
its existing modal acquire/release operations for the slice controller; the
foundation modal's behavior remains covered by its unchanged test. Narrative
blocks movement and residual velocity, owns user focus, and consumes confirm
once per press. Pause retains the original cursor; returning restores the view.
Closing narrative removes the modal mapping context, retains exploration
mapping, restores viewport focus, and leaves no choice widget active.

Actual keyboard movement after travel advances X, keeps Z=0 and moves the
accepted orthographic camera by the pawn's displacement. Swept collision stops
the pawn at the authored boundary. The visible exploration indicator reports
VN-seen and Field invocation count; it is hit-test invisible and owns no modal.

## Defects corrected and limits

- UMG navigation return type, hidden member name, explicit CreateWidget class,
  TObjectPtr deduction and UE5.8 JSON shared-string conversion were corrected
  against installed engine headers; failed build logs remain preserved.
- The new oracle adapter initially mixed spaces/tabs; only the adapter was
  corrected. Source scripts were not edited.
- The first PIE test called both AutomationOpenMap and FStartPIECommand. The
  former already creates PIE in UE5.8, so the second replaced the test session
  and left its observer holding a stale raw pointer. Removing that extra start,
  using a weak observation handle and checking current owned state resolved the
  test crash. Actual VN travel/skip had already executed. The failed attempt's
  log/captures are retained and are not counted as a pass.
- Render review found an incorrectly rotated development text actor and
  unbuilt static lighting notices. A read-only exploration status view replaces
  the label, and the three owned fixture maps use dynamic lighting. The bounded
  refresh command refuses any map with a different GameMode. Removing an actor
  from an unloaded editor map required EditorDestroyActor rather than the
  runtime Destroy call and direct iteration of the loaded persistent level;
  active-level iterators omit actors in these commandlet worlds. Final captures verify removal.

Limits: no production New Game reset/Ch1 history, final Verdan, NPCs, trade,
shops, battle, portraits/CG/audio, final typography/animations/transitions,
cook/package or full campaign parity. Text is immediately visible; production
typewriter/backlog/read-state pacing is deferred. English rendered evidence
does not certify final Korean font layout. The development fresh run uses the
accepted catalog bootstrap defaults, not the full source New Game/profile/
inventory reset. Chapter metadata is preserved and does not itself advance
the run. The resolver accepts only this imported sequence and one map alias.
Physical USB controller testing is not claimed; keyboard/gamepad events are
