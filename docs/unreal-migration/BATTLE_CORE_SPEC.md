# 전투 핵심 루프 명세 (다음 단계, S294 제안)

> 대상: Codex 다음 작업. 작성 2026-09-26. 기준: `792034ff`(전체 렌더 스위트 286/286 통과) 위에 사운드 1차를 얹은 Claude 레인 커밋(`claude-handoff.md` 참고).

## 목표

베르단 재방문 전투에서 **기억을 태울지 말지가 실제 결과를 바꾸는** 한 판을 끝까지 플레이할 수 있게 한다.
지금은 전투 진입 후 FLEE(도주)만 가능하고, 화면에 "Attack / burn unavailable"(공격·연소 불가)이 표시된다.

플레이어가 느껴야 하는 것:
- 평타만으로도 이길 수 있지만 느리고 아프다.
- 기억을 태우면 한두 턴에 끝나지만, 그 기억은 서고에서 사라지고 결과가 전투 밖에도 남는다.

### 이번에 제외 (다음 단계)

리밋 브레이크(Memory Cascade), 자세 3종, 메모리 에코, 잔존 기억 연소, 증언(Witness) 행동, 엘리아 기술과 쿨다운, 세이블·토비아스, 자동 전투, 전투 속도, 보스 페이즈.

증언은 "태우지 않고 푸는" 경로라서 이 게임의 핵심 긴장의 반쪽이다. **이번 단계 바로 다음 작업**으로 둔다.

## 규칙은 원본과 정확히 맞춘다

- **수치 규칙은 Godot 오라클로 검증한다.** 규칙은 피해 계산, RNG 뽑는 순서, 상태이상, 보상, HP다.
  - `Unreal/Tools/export_battle_entry_oracle.py`를 확장해 `export_battle_core_oracle.py`를 만든다.
  - 행동 시퀀스와 기록된 RNG 스트림을 입력하고, 단계마다 플레이어·적 HP, 상태, 게이지, 로그 키, Grains, 연소 기록을 비교한다.
- **RNG는 `FMemoriaEncounterRng`처럼 주입한다.** 원본의 `randi_range`/`randf` 호출 순서를 그대로 지킨다. 예: 공격 `0~10` → 적 능력 확률 → 가중치 선택 → 능력 수치 → 드롭.
- **챕터 주의.** 재방문 전투는 3장 상태(`CurrentChapter=3`)에서 일어난다. 그래서 아렐의 공격력은 `15 + (3-1)*3 = 21`, 최대 HP는 130이다(`BeginEncounter`가 이미 적용). 3장이라는 전제는 오라클 입력에도 명시한다.
- **최소 오라클 케이스** (각각 한국어·영어):
  1. 평타만으로 골목쥐 격파
  2. 5등급 연소 1회 후 평타로 마무리
  3. 3등급 이상 연속 연소 → 연쇄 배율
  4. 2등급 연소 → 적 화상 DoT
  5. 방어 → 피해 절반 + 방어 집중 분기 3종
  6. 포션·해독제·화염탄 각 1회
  7. 독(골목쥐)이 걸린 상태에서 해독제
  8. 약화(시장 도둑) 상태의 평타 피해
  9. 부패 수정자로 붙은 `shield` / `reflect` / `charge` / `stun` / `drain` 각 1회
  10. 약점 적중으로 BREAK 발동 → 스태거 2턴
  11. 최후의 저항 → 패배
  12. 승리 보상: 드롭 있음·없음
  13. `keep_memory` 목표 성공·실패
- 퇴색·담보·이미 탄 기억은 선택할 수 없다. 연소는 `UMemoriaRunSubsystem::BurnMemory` 한 곳으로만 간다(런 컨텍스트, 오염 방지).
- 해결 도중(적 턴 처리 중)에는 런 델리게이트를 브로드캐스트하지 않는다. 내러티브 인터프리터처럼 이벤트로 기록하고, 해결이 끝난 뒤 호스트가 처리한다. 관찰자가 런을 교체해도 안전해야 한다(기존 `Cancel*` 테스트 패턴 유지).

## 연출과 손맛은 플레이해서 판단한다

원본 값을 **출발점**으로 쓰고, 직접 플레이하면서 조정한다. 이 부분은 오라클 대상이 아니다.

| 요소 | 원본 출발값 | 위치 |
|---|---|---|
| 공격 예비 동작 | 0.23초 후 피해 | `battle_manager.gd:1623` |
| 적 공격 예비 | 0.2초, 능력 예고 0.5초 | `:2211`, `:2255` |
| 적 턴 전 대기 | 0.8초 | `:2688` |
| 히트스톱 | 피해 30+ 0.05초, 80+ 0.08초, 200+ 0.12초 | `battle_scene.gd:3640` |
| 화면 흔들림 | `clamp(피해/60, 0.5, 3.0)` | `:3687` |
| 큰 타격 | 80+ 화면 섬광, 150+ 컷인, 200+ 줌 펀치 | `:3690` |
| 피격 스쿼시 | 적 1.15×0.85 → 0.95×1.05 → 1.0 (0.04/0.06/0.08초) | `:3658` |
| 연소 컷인 | "기억 연소 / 힘은 오르지만, 대가는 전투 뒤에도 남습니다" | `:3737` |
| 데미지 숫자 | 대상 위 떠오름, 회복은 음수 | `battle_vfx.gd` |

- **사운드:** 사운드 1차 작업에서 `UMemoriaAudioSubsystem`(게임 인스턴스 서브시스템)이 들어온다.
  - **효과음 호출:** `GetGameInstance()->GetSubsystem<UMemoriaAudioSubsystem>()->PlaySfx(TEXT("<원본 이름>"))`로 호출한다. 전투용으로 이미 렌더된 큐는 다음과 같다: `sword_slash`, `burn_ignite`, `shield_break`, `heal`, `heal_layered`, `hit`, `drain`, `shield`, `flee`, `defeat`, `enemy_die`, `phase_change`, `ui_select`, `memory_add`, `rising_tone`.
  - **전투 BGM:** 전환(`battle_theme`)과 복귀는 서브시스템이 이미 처리한다.
  - **자동 재생:** 등급 2 이상 기억을 연소하면 원본의 연소 드라마(정적 → 상승음 → 점화)가 기억 도메인 이벤트만으로 자동 재생된다. 전투 코드에서 따로 호출하지 않는다.
  - **저체력 심장박동:** 루프 에셋(`S_Amb_heartbeat`, -14 dB, 원본 `update_low_hp_audio`)만 준비돼 있다. 서브시스템에 켜고 끄는 메서드를 추가해 연결한다.
- **연출 검증:** 캡처 3~4장(연소 순간, 큰 타격, 승리 보상, 패배 화면)과 아래 플레이 점검이면 충분하다. 신호 하나마다 증거 폴더를 만드는 방식은 연출 작업에 쓰지 않는다. 증거 폴더는 이제 git 밖(로컬 전용)이다.
- **개발 문구 제거:** 전투 화면의 "Development slice: entry and withdrawal only…" 문구는 이 단계에서 없앤다.

## 작업 순서 제안

1. **도메인 먼저:** `FMemoriaBattleModel`(엔진 비의존, 주입 RNG)에 행동·적 턴·상태이상·보상을 둔다. 먼저 오라클 케이스를 통과시킨다.
2. **서브시스템 연결:** `UMemoriaBattleEntrySubsystem`을 전투 세션으로 넓힌다(또는 `UMemoriaBattleSubsystem` 신설). 이때 소유 월드·런 교체 취소 규칙은 그대로 유지한다.
3. **UI:** 기존 전투 위젯의 FLEE 자리에 행동 4개와 도주를 둔다. 연소 선택 목록은 서고와 같은 등급 색·상태 표기를 쓴다.
4. **연출과 사운드:** 위 출발값을 적용하고, 직접 플레이하며 조정하고, 캡처한다.
5. **증언 행동(다음 단계):** 태우지 않고 푸는 경로를 넣어 긴장의 나머지 반쪽을 채운다.
